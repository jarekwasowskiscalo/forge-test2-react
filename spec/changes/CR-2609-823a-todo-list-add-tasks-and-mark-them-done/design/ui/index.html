To answer: say “approved”, or name a choice or a panel and what to change — for example “C-1: keep Guestbook”, “C-17: no success toasts”, “P6: add a counter”.

Not drawn, and why

  • R-9, two people changing one task at once: no screen state. The later change wins and nobody is told (todo_list.md § Deliberate non-goals).
  • todo_task_empty_patch (“No change was given. The task is unchanged.”): this screen never sends a change without a text or a done mark.
  • The standard validation refusal (FastAPI's list): only a malformed request earns it, and this screen never sends one.
  • Live updates: a non-goal; other people's changes appear when the list is read again (R-3.5).
  • Other window classes: .specconf/stack.json § window_classes declares none, and a phone layout is a named non-goal (spec/invariants.md). The column narrows with the window, as the guestbook's does.
  • Other languages: English only (Q-7, conventions.md § Language).
  • A dark theme: withdrawn (system-states.md § One palette); theme.css has one palette.
  • Search, filters, pages, “clear all done”, reordering, dates, owners: non-goals (todo_list.md).
  • Focus inside the dialog, the Tab cycle, Escape: the Modal primitive's behaviour, unchanged; described under P8, not drawable.
  • A write that waits a long time (E-27): nothing beyond P10's markers, which stay until the answer.
  • A largest number of tasks: none is set (todo_list.md § Open questions); P15 shows 101.
  • The guestbook's own states: unchanged; P17 draws only what the frame changes there.

Contradictions and observations

  • Contradiction — how long a failure toast stays. system-states.md § Toast says a toast “disappears on its own”; frontend/src/components/ui/Toast.tsx keeps error toasts until they are dismissed. The failure toasts here (C-18) are drawn with their dismiss button, as the code behaves, and the unchanged screen carries the lasting fact. This decides how long the R-10 message stays; the screen specification should settle it.
  • Contradiction — the empty-state primitive. system-states.md § Components lists EmptyState; Feedback.tsx records that it was removed (requirements.md § Impact analysis already notes this). The empty sentence is drawn inline, as the guestbook's is (design/delta/architecture.md decision 5).
  • Contradiction — sizes off the scale. system-states.md § Tokens allows sizes outside the Tailwind scale (“rounded-[14px] … allowed”); theme.css § Radii and conventions.md § Frontend require a token or the scale. This page uses tokens and scale steps only.
  • Observation — colours outside theme.css in two live primitives. The toast glyphs use Tailwind's own green, amber and red, and the dialog's backdrop is black at 45%, against system-states.md § Tokens (“named tokens only”). They are drawn here with tokens (an inverse tick, a danger dot, ink at 45%). This change does not touch them.
  • Observation — field edges. Field edges use --color-hairline, as on the guestbook, which is below the 3:1 WCAG 1.4.11 asks of a control's edge. The focus ring marks the field while it is focused. Only the new checkbox is given a stronger edge (C-12).
  • Observation — typefaces. This page loads nothing from the network, so Instrument Serif and Instrument Sans show only if installed. Otherwise the token stacks fall back to Georgia and the system sans, as the built screen does when the font host fails.
