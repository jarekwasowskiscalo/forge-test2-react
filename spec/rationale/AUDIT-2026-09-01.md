## 0. Executive summary

### Verdict

**This is a very well designed process framework with a small, clean example application —
and with one systemic gap: the framework is not applied to itself.**

The engineering quality is high and unusually consistent. The code carries its reasons
(article IX), names the incidents that shaped it, and in a dozen places argues *against* the
simpler solution while stating the price. The gates are real rather than decorative. The
infrastructure's security is done correctly the first time: OIDC instead of keys, IAM instead
of a password, OAC instead of a public bucket, `rds-db:connect` narrowed to one user.

The problems I found fall into three classes and only one of them is about code:

1. **The process has not a single piece of evidence of execution in this repository.** Zero
   change records. Five content checks pass *emptily* rather than evidentially, and seven
   diff-scoped ones do not run at all. The whole last wave of work — Lambda, IAM, the rebuilt
   frontend, four new ADRs — lies uncommitted on `main`, outside the process this repository
   exists to enforce.
2. **Two gates measure the same thing differently.** `gate.py` does not know the third state
   `check.sh` knows. The effect is hard: on a machine without Docker no stage can close green,
   although a profile designed for exactly such a machine exists — and the default path does
   not even reach that verdict, because it dead-ends earlier.
3. **Several [CRITICAL] rules have no mechanism behind them**, and one of them is broken 33
   times today.

# PART A — FLOW: the SDD process and the skills directory

## A1. The process model

The chain of stages:

```
intake → requirements → design → plan → implement ⇄ debug → clean_room
       → spec_sync → deliver → closed
                        ↘ review_fix → {requirements|design|implement|clean_room}
```

The path (tier) is determined by **arithmetic, not conversation** — and that is the single
best design decision in this framework. `cr-impact` measures eight signals, records them with
the verb `change_state.py set-signals` (both halves — the lit and the unlit, because "not
lit" is a measurement and silence is not), and `process_config.py` computes the tier from the
rules in `.specconf/process.json`.

`.specconf/process.json` documents why it exists: a change with four requirements and 143
lines of code took the strategic path, because the tier was assigned by conversation before
anything was known. Three asymmetries pushed upwards — a default of `p2` in the middle of the
scale, one-sided friction (raising is always allowed, lowering is not) and the absence of an
arithmetic anchor. The file removes the third.

| Path | Compositions | Steps | Plan turns | Ladder | Rounds |
|---|--:|---|---|--:|--:|
| `p0` correction | 4 | 2–6 | 40–130 | ×1 | ×0 |
| `p1` minor | 16 | 10–19 | 172–339 | ×2 | ×1 |
| `p2` standard | 40 | 9–21 | 160–369 | ×3 | ×2 |
| `p3` strategic | 40 | 10–22 | 180–389 | ×3 | ×3 |

**The label does not order the cost** — and the tool says so itself: `p1` reaches 339 turns
while `p2` starts at 160. That is a kind of honesty one does not see in configurations of
this sort.

### What is exemplary here

- **Versioning the configuration schema with a rationale per version.** `schema_version: 3`,
  and the comment on each version says what a reader of the previous one would misunderstand.
  That is rare and expensive to invent after the fact.
- **The rule for choosing a condition is written down and falsifiable:** "a step's condition
  is the same predicate as the gate that would fail without that step". Plus the sentence that
  turns it into a measurement: "where the condition and the gate diverge, exceptions are born
  — and that is a measurable definition of a well-chosen condition rather than a matter of
  taste".
- **`build-tests-unit` deliberately unconditional**, citing article III and naming the
  alternative: "conditioning it on a signal would be an escape hatch with no expiry date".
- **Every number has a measurement behind it.** `convergence_deep_rounds: 1` is not a hunch —
  it is an answer to a measured 26 dispatches, 154 USD and four hours of one stage.

### `skill_gate` — one implementation instead of a hundred and twenty files

`skill_gate.py`'s docstring names the thing outright: the reference implementation writes a
`<skill>_preflight.py` and a `<skill>_verify.py` per skill — "around a hundred and twenty"
files (`skill_gate.py:3-4`), and expressing the path table as separate files would cost
"Twenty-four" (`:11`). **Both numbers are stale today**: 39 skills is 78 files, and 29
contracts is 58. The argument stays sound, its arithmetic does not — and nothing holds it,
because these are numbers in prose rather than paths (cf. F-02). Here almost every skill asks
the same four questions (is the change at the right stage, do my inputs exist, did I produce
my outputs, did a state field move), and they differ only in *which* paths and *which* field.
So the per-skill knowledge lives in the `CONTRACTS` table, and the behaviour lives once.

A contract carries: `stage`, `requires`, `produces`, `reads`, `min_chars`, `optional`,
`state_verbs`, `turn_budget`, `append_only`, `after`, `verifies_worktree`.

**This is the right decision and it is well executed.** Ten skills stand outside that table
and **none of them is a second implementation** — I checked all fourteen files: they are
identical sixteen-line shims over `sdd.skill_brief`, a second shared engine whose brief is a
state and a focus rather than a worker's contract. There is no divergence; there is an
unwritten boundary and stale numbers — that is what F-11 is about.

> `review-converge` HAD NO entry here, and `skill_gate` then falls back to the change

### F-02 — G10 has a blind spot for directories

`check_specs.py:535`:

```python
if "/" not in token or token.endswith("/"):
    return False
```

A token ending in a slash **is not path-shaped**, so every reference to a directory in
backticks — and that is how this repository names most things — is out of G10's reach. It
falls out **on that line and never reaches the later ones**. There are four filters in total
(535, 539, 542, 544), and the last of them — the requirement of a known extension from
`_PATH_EXT` — cuts out a **second** class: a bare file name with no slash, like
`Guestbook.dc.html` from F-14. Two blind spots, two different conditions, and both have a
live specimen in the tree today.

`CLAUDE.md` describes G10 as "every repository path named in backticks exists". The
implementation says: *every file with a known extension, under an existing top-level
directory*.

**The live evidence is in the tree.** The docs/ directory does not exist, and it is named in
backticks in **five** places — three that G10 would see (`spec/design/conventions.md:154`,
`spec/ADR/ADR-0007-interface-copy-is-in-english.md:52`,
`.claude/skills/reconcile-design/SKILL.md:87`), and two in Python prose that G16 would see
(`.claude/skills/_shared/sdd/stages.py:590`,
`.claude/skills/_shared/sdd/test_sdd_process_config.py:710`). G10 checked 697 paths and
reported none; G16 checked 146 and also none.

A sixth mention, `.claude/skills/reconcile-docs/SKILL.md:3`, is without backticks — and that
is the one carrying F-09.

The irony is doubled: G16 came about **from exactly this class of failure** — five live
pointers at a deleted file, two of which appeared *after* the deletion, "so the reference did
not merely survive, it multiplied". The same dynamic is at work today at the directory level
and neither gate sees it, because both share `_path_shaped`.

### F-06 — the data model does not know about search

`BR-05` ("the guestbook can be narrowed by a phrase and read a piece at a time") is described
in the context, published in the contract (`api.md:96` — the `q` parameter, ≤ 200 characters)
and implemented in `app/services/guestbook_entries.py`:

```python
return or_(
    GuestbookEntry.author.icontains(phrase, autoescape=True),
    GuestbookEntry.message.icontains(phrase, autoescape=True),
)
```

`icontains` renders as `ILIKE '%phrase%'` on two columns joined by `OR` — a query **no
ordinary B-tree index serves** (a leading wildcard). In Postgres that needs `pg_trgm` and a
GIN index.

`spec/design/data-model.md` does not mention `q`, search, or any index other than the ordering
one. A grep for `search|ilike|phrase` in that file: **zero hits.**

The document declares of itself: *"Every change to this document is a revision, and the other
way round"* — and here the rule, the contract and the code changed, and nothing here did.
Worse, the document already contains a ready argument against this state, formulated for the
sort order:

> An order promised by the contract with no index behind it means a full sort of the table
> every time the only screen is opened — invisible while the table is small.

The sentence applies to `q` word for word. There is a second cost too: `list_entries` with a
phrase runs **three queries** — a `COUNT(*)` of the whole table, a `COUNT(*)` with `ILIKE`,
and a `SELECT` of the page — two of which are full scans. The screen calls this after every
bounce of the debouncer.

This is not a defect in the code: the code does exactly what the contract promises. It is a
**missing design decision**, and it is a direct effect of F-03 — work outside `/sdd` did not
run the `design-data` step, so there was no author whose write set covers this file.

**Recommendation.** Do not add an index reflexively — add a *decision*: either a row in
`data-model.md § Indexes` with a `pg_trgm` GIN index and a migration, or an explicit sentence
saying "search is a sequential scan and is meant to be, because the guestbook is small", with
a threshold at which that stops holding. Silence is the one answer that does not work here.

### F-18 — the justification for the frontend junit upload is untrue

`ci.yml:379-380` defends that upload with the sentence:

```text
The junit reporter does not capture console output — vitest writes attributes and
assertion text only.
```

**This is untrue for the vitest 3.2.7 this repository has installed.** The junit reporter sets
`this.options.includeConsoleOutput ??= true` and at that value writes `<system-out>` and
`<system-err>` from the captured output, and inside `<failure>` the full error body. The type
declaration says so outright: "Write `<system-out>` and `<system-err>` for console output —
**@default true**". Nothing in this repository turns it off.

The effect is that the `frontend-junit` artefact carries **more** than the backend report the
rule on lines 251-256 forbids — because on the pytest side `junit_logging = "no"` at least
removes the captured body. The justification is worse than no justification at all: a sentence
that falsely closes a question costs the next reader as much as checking would have.

**Recommendation.** If the upload stays, add `includeConsoleOutput: false` to the reporter's
configuration and correct the comment. If it goes — delete both together with F-05. What must
not be left is a sentence saying a library does something that library does not do.

### Cost as a design decision

`min_capacity = 0` in Aurora Serverless v2 — "between requests the cluster scales to zero and
the bill is the storage alone". The price: 10–15 seconds to resume after quiet, which is why
the API function has a 30 s timeout and production sets a non-zero floor. The proxy is a
per-environment choice, because "it is billed hourly regardless of whether anything connects".
`dev` goes without a proxy, `stage` and `prod` have one.

The absence of a NAT gateway is a decision `app/db/iam_auth.py` stands on: a password from
Secrets Manager would need a route to Secrets Manager, and that "costs every hour, regardless
of whether anybody visits the guestbook". The IAM token is **signed locally** — SigV4 over the
endpoint, the port and the user, from credentials the runtime already has. Zero round trips,
zero route, nothing to rotate.

**This is an example of cost engineering done well:** an infrastructure decision and a decision
in the application's code are the same decision, and both say so.

## B9. The serverless layer

`app/lambda_handler.py`: two functions in one zip package — `handler` (Mangum over an
unchanged `app/main.py`) and `migrate` (a release step). One artefact, "because it is the same
code against the same schema — a migration built from a different commit than the code it
prepares is a failure this arrangement is meant to make unrepresentable".

The migration **does not run at start**, because "a container that migrates at start races
every other replica starting beside it, and Lambda can start a hundred execution environments
in a second".

`_ensure_iam_login()` is idempotent by construction rather than by a flag ("there is no 'has
this run already' flag that can be set wrongly"). The role **owns nothing**: it reads and
writes rows, it cannot create or drop tables — "so a defect in the API cannot reshape the
database, whatever it does to the data". Schema changes go through Alembic, under the master
user.

The role's name is **validated** rather than quoted-and-hoped: `user.replace("_",
"").isalnum()`, because an identifier cannot be bound as a parameter. The comment honestly
says this is a guard against a typo rather than against an attacker, "who has no way to set
it".

`scripts/zip_deterministically.py` exists so that the package is reproducible — correct.

## Closing

The thing worth saying at the end, because the findings register does not convey it: **this
repository is written better than most production systems.** The justifications in the code are
real and expensive to invent after the fact. The gates catch things that really happened, and
say so in a comment. Detectors arrive with a test that they detect. The configuration is
versioned with a note on what a reader of the previous version would misunderstand. The
infrastructure's security is done correctly the first time, without a single error findable
from reading.

Twenty-two findings in a repository of this density is a low number, and eleven of them are
minor items and observations (one critical, ten serious, four minor, seven observations).

The pattern connecting them, though, is a single one and worth naming: **enforcement went where
the authors were once punished, and rules written preventively were left without a detector.**
The layers have a test, because they once diverged. The second database engine has a test,
because it once cost something. Magic pixels, `create_all()`, the forbidden file names and the
directory half of G10 have nothing — and the first of those is broken thirty-three times today.

That pattern has a natural remedy and it is the thing in recommendation 11: **carry one real
change through this process.** A framework that has never run on its own repository is a set of
hypotheses about what a gate will catch — very well justified, tested in 1 280 places, and
still hypotheses. The first change record will turn five gates from empty into evidential, give
work to seven more that do not run at all today, and be worth more than all the other
recommendations combined.
