# Publish both shapes of the 422, and stamp a 500 like every other response

GitHub issue #25 — audit findings `A25` and `A26`, both confirmed, both P2. Joined because
both are the same sentence about the same file: the shape of an error response was not
uniformly governed, and `app/core/errors.py` is where both halves live.

## What changed

- `app/contexts/guestbook/routers/guestbook_entries.py` — the `422` on `PATCH` is declared as
  `_EITHER_REFUSAL_OR_VALIDATION`: an `anyOf` over `Refusal` and `HTTPValidationError`, written
  as raw `$ref`s. It used to declare `Refusal` alone.
- `contracts/openapi/guestbook.yaml` — that `422` gains a `content` with the same union;
  `HTTPValidationError` and `ValidationError` are declared in `components/schemas` so the two
  references resolve inside the document; `info.version` `1.1.0` -> `1.2.0`.
- `frontend/src/api/schema.d.ts` — regenerated by `./scripts/generate.sh`, never edited. Two
  lines: the description, and `Refusal` becoming `Refusal | HTTPValidationError`.
- `app/core/errors.py` — adds `CatchAllMiddleware`, a pure-ASGI layer that catches an unhandled
  exception, writes the one application record, answers with the fixed `500` body and re-raises.
  `_handle_generic_exception` keeps returning the identical body and now logs only when the
  scope carries no `app_unhandled_logged` flag. The body is a module constant, `_SANITIZED_500`,
  because two layers answer with it.
- `app/main.py` — `app.add_middleware(CatchAllMiddleware)` **before** `RequestIdMiddleware`,
  which is what makes it the innermost of the three.
- `tests/unit/test_error_response_envelope.py` (new) — three tests: a `500` on a preview, the
  same outside one, and two overlapping requests.
- `tests/integration/test_guestbook_entries_contract.py` (new) — twenty-two parametrised cases
  plus two named ones, validating real bodies against the published schema.
- `pyproject.toml`, `uv.lock` — `jsonschema>=4` in the `dev` group, for that test and nothing else.
- `spec/design/api.md` § Refusals, `spec/design/architecture.md` § Platform (the
  `app/core/errors.py` row, and a dated `Rejected` block for the layer-order decision),
  `docs/security.md`, `docs/operations.md`.
- `tests/tooling/test_lambda_package.py` — the test that builds the Mangum adapter now creates
  and closes the event loop itself. Not cosmetic: see below.
- `spec/changes/EXEMPTIONS.md` — two dated rows. **Delete them once this has merged.**

## Why

**The published `422` on `PATCH` described the rarer of two shapes, and suppressed the other.**
Six ways exist to earn a `422` on that route. One is the coded refusal
`guestbook_entry_empty_patch`. The other five — an empty field, an over-long field, a wrong
type, an unreadable id in the path — are Pydantic's, and answer with a **list** under `detail`.
Declaring `422: {"model": Refusal}` said all six were the first. Worse, an explicit `422`
*replaces* the `HTTPValidationError` FastAPI would have generated, so the shape a caller meets
most often vanished from `openapi.json` and from the generated types, and no consumer could
describe it at all.

Nothing caught it. `contracts/openapi/guestbook.yaml` declared that response with a
`description` and no `content`, and `scripts/openapi_contract.py` skips a response with no JSON
body — so it counted towards "10 responses" while nothing about it was compared. That gate
reads two documents and never sends a request; the missing capability is a test on real
responses, not a change to the gate, whose subset design is argued in its own docstring.

**A `500` was the one response that carried neither `X-Request-ID` nor `X-Robots-Tag`.**
Starlette composes the stack as `[ServerErrorMiddleware] + user_middleware +
[ExceptionMiddleware]`, so the layer that catches an unhandled exception is built outside every
`add_middleware` middleware and answers through the server's raw `send` — past both
`send_with_header` wrappers. `docs/operations.md` promised the id on every response and
`docs/security.md` promised `noindex` on every preview response, without exception. A crashed
route kept neither promise, and `tests/unit/test_robots.py` could not see it: it covers a `200`
and a routing `404`, and a routing `404` is raised *inside* the wrappers.

The audit's third claim — that the ERROR log line also lost the id — was already false when
this was picked up. #40 fixed it on 2026-09-16 by not resetting the contextvar on the failure
path. Measured before changing anything: `error_log_has_id: true`.

**And one leak that was already there, which this is the first change able to see.** Mangum's
constructor calls `asyncio.get_event_loop()`; with no current loop that *creates* one and
installs it as the thread's, and nothing ever closed it.
`tests/tooling/test_lambda_package.py::test_reading_the_handler_builds_it_once_and_keeps_it` is
the only place that builds an adapter, so that orphan has been sitting in every backend run —
invisible, because nothing cleared the reference that kept it alive. The new concurrency test is
the first code in this repository to call `asyncio.run()`, and its teardown sets the current loop
back to `None`; the orphan is then collected unclosed, and `filterwarnings = ["error"]` turns the
`ResourceWarning` into a failure of whatever test happened to run last. Bisected to that one test
by deselecting it (`782 passed, 1 deselected`, clean) and fixed where it is caused rather than
suppressed where it surfaced.

## From what, to what

**Before.**

- `PATCH .../{entry_id}` published `422` as `Refusal`; five of its six `422` cases returned
  something else. `schema.d.ts` typed it `Refusal`.
- An unhandled exception answered `{"detail": "internal server error"}` with
  `content-length` and `content-type` and no other header.
- One unhandled exception produced two application records under a test client, and the
  `500` handler always wrote one.

**After.**

- That `422` publishes `anyOf: [Refusal, HTTPValidationError]`; `schema.d.ts` types it
  `Refusal | HTTPValidationError`. Component names are unchanged — renaming one would itself
  be a break.
- The same `500` body leaves carrying `X-Request-ID`, and `X-Robots-Tag: noindex, nofollow`
  where the environment calls for it — which is still decided in `app/main.py` alone.
- One unhandled exception produces exactly one application record.

Nothing on the wire changed for `A25`: the bodies are the same bytes. What changed is that the
document now describes them.

## How it works now

`app/main.py` adds three middlewares. `add_middleware` inserts at the front of the list and the
front of that list is the outermost layer, so the **first** one added is the **last** one
entered. The chain, outside in:

```
ServerErrorMiddleware -> NoIndex -> RequestId -> CatchAll -> ExceptionMiddleware -> router
```

`CatchAllMiddleware` catches an unhandled exception inside both header wrappers, marks the ASGI
scope, logs, sends the fixed body through its own `send` — so both wrappers stamp it on the way
out — and re-raises. `ServerErrorMiddleware` then calls `_handle_generic_exception` as it always
did; the response has started, so Starlette skips its own send, and the scope flag makes that
call silent. Only the re-raise is left, which is what keeps
`TestClient(raise_server_exceptions=True)` — the default the suite runs on — surfacing a real
traceback when a route fails by accident.

The flag is on the scope rather than in a module-level variable: the scope is per request and is
the same object `ServerErrorMiddleware` wraps in its `Request`, so nothing is shared between
requests and nothing needed a contextvar of its own.

For the contract: a status code that can carry two shapes is declared as two, in the router, in
the hand-written contract and therefore in the generated types. Whether a body actually matches
what was declared is now answered by sending the request.

## What it means for the process

Nothing about running or changing this repository moves. Two things are worth knowing:

- `jsonschema` is a new `dev` dependency, so a clone needs `uv sync` before the integration
  suite runs. `uv.lock` carries it.
- `contracts/openapi/guestbook.yaml` is at `1.2.0`. The next contract edit raises it from there.

The `spec-exempt` label is on the pull request, and `spec/changes/EXEMPTIONS.md` carries the row
that gives it a reason and an expiry. The row covers this pull request and nothing else — delete
it once this has merged, as #43 did for #40.

## What it does not change

- **No response body changed.** `A25` is a documentation defect; the bytes on the wire for all
  six `422` cases are what they were.
- **The `X-Robots-Tag` decision did not move.** It is still the one `if` in `app/main.py`, which
  `tests/unit/test_robots.py` holds by reading that file as text. The `local` variant of the new
  `500` test exists to prove the repair did not quietly widen it to stage and production.
- **`scripts/openapi_contract.py` was not "fixed" to demand `content` everywhere.** Its subset
  design is deliberate and argued; the missing capability was added as a test, not as a gate change.
- **`request_id.py`'s asymmetric set/reset is untouched.** #40 put it there on purpose and
  `tests/integration/test_app_integration.py` pins it.
- **The `mangum.adapter` warning filter in `pyproject.toml` stays.** The test now installs a loop
  before Mangum looks for one, so it no longer reaches that deprecation — but the library still
  behaves that way and Lambda still triggers it. The filter describes the library, not the test.
- **No ADR.** `spec/design/conventions.md` § When a decision is an ADR forbids one until the
  first change has gone through `/forge:sdd`; the layer-order decision is recorded as a dated
  `Rejected` block in `spec/design/architecture.md`, which is the route that section names.
- RFC 9457 (`problem+json`) is still the stated destination of `frontend/src/api/problem.ts` and
  is still not this change: it alters response bodies, which is a major version and a separate
  design decision.

## How it was verified

Both halves were made to fail first, on this tree, before any application code was touched.

- `./scripts/test.sh integration tests/integration/test_guestbook_entries_contract.py` —
  **6 failed, 120 passed**, and the six were exactly the PATCH cases the finding names: empty
  author, over-long author, over-long message, wrong type, non-UUID id (plus one case of mine
  that named a query parameter the route does not have, since corrected).
- `./scripts/test.sh unit tests/unit/test_error_response_envelope.py` — **3 failed**, with
  `assert None == 'audit-123'` for `x-request-id` on the `500`.

After the change: `backend` 783 passed and 1 skipped, `fitness` 233 passed, `e2e` 44 passed
(30 scenarios plus the UI smoke), `./scripts/lint.sh` OK (ruff, `mypy --strict`, eslint, tsc),
`./scripts/contracts.sh` 0 problems, `./scripts/generate.sh` clean, and
`./scripts/check.sh` **OK** end to end.

`POSTGRES_HOST_PORT=5492` was needed for the e2e leg on this machine: a container from an
unrelated checkout holds `:5432`. That is what the variable is for (`docker-compose.yml` says so),
not a property of this change.

`sdd-specs` is green on all thirteen content checks and on `exemptions` over four rows. The one
diff-scoped gate left red is `change-directory`, which is what the `spec-exempt` label clears on
the strength of the register row — the same shape as #40.

The two new contract components were shown to be load-bearing rather than decorative: changing
`ValidationError.msg` to `type: integer` turned `./scripts/contracts.sh` red, and the file was
restored.

**Not run here:** CI's cross-platform (macOS) leg, `package.sh --lambda`, the production image's
runtime assertions, the routing verdict and the frontend suite census —
`spec/design/testing.md` § What only CI can answer. Those are answered by the pull request run.
